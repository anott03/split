# AGENTS.md

## Project Shape
- Single-package `pnpm` app: Next.js 16 App Router + React 19, deployed to Cloudflare Workers through `@opennextjs/cloudflare`.
- Runtime data is Cloudflare D1 via Drizzle; the schema source of truth is `src/lib/schema.ts`.
- Main app flow: `src/app/page.tsx` validates the Better Auth session, loads the active group/expenses/balances, and renders `src/components/dashboard.tsx`.
- Server mutations live in `src/lib/*-actions.ts` and must validate session plus group membership before touching D1.

## Commands
- Install/use dependencies with `pnpm`; `pnpm-lock.yaml` is the lockfile.
- Dev server: `pnpm dev`. `next.config.ts` calls `initOpenNextCloudflareForDev()` so `getCloudflareContext()` works during `next dev`.
- Reliable local verification: `pnpm exec tsc --noEmit` and `pnpm build`.
- Cloudflare worker build: `pnpm worker:build` writes `.open-next/worker.js` and assets.
- Cloudflare preview/deploy flow: `pnpm preview`, `pnpm upload`, or `pnpm deploy`; each runs an OpenNext build first.
- D1 schema push: `pnpm db:push`; it uses `drizzle.config.ts` and requires `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_DATABASE_ID`, and `CLOUDFLARE_D1_TOKEN` in the environment.
- Regenerate Cloudflare binding types after changing `wrangler.jsonc`: `pnpm cf-typegen`.

## Current Tooling Gotchas
- `pnpm lint` is not a valid verification step right now: the script is `next lint`, which fails under this Next version by treating `lint` as a project directory.
- `pnpm exec eslint .` also currently fails with the checked-in flat config/Next ESLint config combination, so do not present lint as passing unless the config is fixed.
- There is no test runner or test script configured; do not invent one.

## Cloudflare / OpenNext Notes
- `wrangler.jsonc` points Worker `main` at `.open-next/worker.js`; run `pnpm worker:build` before using Wrangler output directly.
- The D1 binding is named `DB`; `src/lib/db.ts` lazily proxies Drizzle because bindings are only available in request scope on Workers.
- `cloudflare-env.d.ts` is generated by Wrangler and references `.open-next/worker`; regenerate it instead of hand-editing binding declarations.
- `wrangler.jsonc` has two `observability` keys; preserve behavior carefully if editing that file because JSONC duplicate-key handling can be surprising.

## Next/Auth Quirks
- Keep `src/middleware.ts` as `middleware.ts` with `runtime: "experimental-edge"`. The comments document an OpenNext/Next 16 workaround; renaming it to `proxy.ts` breaks Cloudflare edge runtime support.
- Middleware only checks for the Better Auth session cookie as a fast gate. Server components and route handlers must still call `auth.api.getSession()` for real authorization.
- Auth routes are in `src/app/api/auth/[...all]/route.ts`; Better Auth is configured in `src/lib/auth.ts` with the Drizzle adapter.

## App Conventions
- Group selection is stored in the `split.active_group` HTTP-only cookie; use helpers in `src/lib/groups.ts` instead of duplicating cookie logic.
- Expenses and settlements share the `expense` table; settlements are rows with `kind === "settlement"` plus a single split row.
- UI uses shadcn/base-nova aliases from `components.json` (`@/components`, `@/components/ui`, `@/lib`, `@/hooks`) and Tailwind v4 imports in `src/app/globals.css`.
